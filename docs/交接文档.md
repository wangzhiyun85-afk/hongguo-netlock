# 红果断网（Hongguo Netlock）交接文档

> 独立小项目：一键禁止/恢复「红果短剧」App 的联网，用于"下载完剧集后断网去广告"。
> 从 `douyin/android/netlock` 模块独立出来，2026-10-24 迁移。

## 1. 这是什么

一个**极简界面**的 Android 小工具（2.2.0 起）：点桌面图标打开一张状态页；同时通知栏常驻一条可操作的常驻通知。

- 2.6.0 起界面只有一张背景图：**联网显示 `on` 图，已断网显示 `off` 图**，点屏幕任意位置切换断网 / 联网。
- 桌面图标固定为 `logo.png`（不再随状态切换），桌面名称固定「红果断网」。

三种操作入口：
- 状态页上点一下（整页可点）
- **常驻悬浮球**（2.7.0 起，主要保活方式）：点一下切换断网 / 联网，长按打开状态页，可拖动
- 通知栏常驻通知的按钮：`断网红果` / `恢复联网`、`系统联网控制`、`退出常驻`
- 桌面图标只用来打开状态页，不再点一下就退出

返回键不会杀掉页面，而是退到后台——**最近任务里保留这张卡片**，长按/下拉可锁定，防止被系统清理。

## 2. 技术方案

- **免 root**：使用 Android `VpnService` 建立一个**本地 VPN**，只把红果（`com.phoenix.read`）的流量收进隧道（`addAllowedApplication`），隧道内读取到的包全部丢弃 → 红果无法联网，其他 App 完全不走 VPN。
  - **2.3.0 起同时接管 IPv4 与 IPv6**：路由为 `0.0.0.0/0` + `::/0`，隧道地址为 `10.8.0.1` / `fd00:8:8:8::1`。2.2.0 只有 IPv4 路由，手机有 IPv6 时红果可走 IPv6 绕过隧道——这正是「断网不彻底、离线播放仍弹广告」的根因。
  - **DNS 一并关死**：VPN 内 DNS 指向隧道黑洞地址（`10.8.0.2` / `fd00:8:8:8::2`），避免系统 DNS 仍走物理网络（DNS 泄漏）。
  - 个别机型不支持 IPv6 地址时，自动退回纯 IPv4 建隧道，保证「至少能断」。
- **桌面图标（2.6.0 起固定）**：直接使用 `logo.png` 生成的 mipmap（含 adaptive icon），**运行时不再调用 `setComponentEnabledSetting` 切换 `activity-alias`**。
  - 原因：禁用「当前任务所用的那个别名」会把整个任务关掉。ColorOS 把 App 贴边缩成小窗时（Activity 已 `onStop`），从通知栏点开关就会触发切图标 → 小窗消失、App 彻底退出，2.5.0 的「可见时推迟切换」也挡不住。
  - 现在状态只由界面背景图和通知文案表示，切开关不会动任何组件状态，小窗可以一直挂着。
  - Manifest 里仍保留 `.Allowed`（唯一桌面入口）和 `.Blocked`（无 LAUNCHER filter，仅兼容旧版桌面快捷方式）；升级时若发现 `.Allowed` 被旧逻辑禁用，会在 `KeeperService.onCreate` 里补回启用（只启用、从不反向禁用）。
- **保活**：
  - `KeeperService`：常驻前台服务 + 常驻通知（`foregroundServiceType="specialUse"`），App 打开后就一直活着；断网开关只切换 `BlockService` 的拦截模式，常驻服务本身不退出
  - **2.7.0 常驻悬浮球（`FloatingBall`）**：用 `SYSTEM_ALERT_WINDOW` + `TYPE_APPLICATION_OVERLAY` 挂一个 40dp、50% 透明的小圆头像（绿圈=联网，红圈=已断网），由 `KeeperService` 创建与销毁。
    - 它不属于任何 Activity / 任务，清理「最近任务」划不掉，窗口可见时进程优先级也更高 —— 比贴边小窗（本质是 Activity）更抗杀；用户也不必一直开着小窗
    - 点一下切换（未授权 VPN 时自动打开状态页去授权），长按打开状态页，拖动会记住位置（`ball_x` / `ball_y`）
    - 服务被系统杀掉后由看门狗/心跳自愈重建，悬浮球随之恢复
  - 通知栏开关：`Notification.Action` 实现（Android 12+ 不允许自定义通知布局，做不出真正的 Switch 控件）
  - `START_STICKY`：被系统杀死后自动重建
  - 开机广播 `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED`：若上次是常驻状态，自动拉起
  - 看门狗：`AlarmManager.setAndAllowWhileIdle` 每 **90 秒**（2.4.0 起，原来 10 分钟）检查一次，常驻服务不在就拉起
  - **2.4.0 自愈**：
    - 常驻服务内部每 60 秒心跳一次，发现隧道掉了就地重建，不用等看门狗
    - 亮屏 / 解锁 / 切换 Wi‑Fi 与移动数据时立即自检并重建（这几种场景最容易静默掉隧道）
    - 从最近任务划掉卡片（`onTaskRemoved`）后 3 秒安排一次自愈
    - `BlockService.onRevoke`：VPN 被系统或其他 VPN 撤销时，5 秒后重试
    - 状态、通知文案、界面背景一律以「隧道是否真的在拦截」为准，隧道掉了界面会立刻变回联网背景
  - 2.5.0 起**不再自动跳转任何设置页**：以前点「开始看剧 · 断网红果」会自动拉起「忽略电池优化」授权页，页面被切到后台，看起来像 App 自己最小化了。现在断网/恢复都只在后台起服务，不会把界面挤走；「忽略电池优化」改为状态卡片上的手动链接（可选）
  - Android 13+ 运行时申请通知权限（系统对话框，无法避免）
  - 最近任务卡片：状态页不 `finish`、不 `excludeFromRecents`，可被 ColorOS 下拉锁定
- **VPN 模式**：**只有断网时才有 VPN，联网时 VPN 完全拆除**（2.3.1 起）。
  - 2.2/2.3.0 为了配合系统「始终开启 VPN」，在联网状态保留过一条「空隧道」；这条空隧道会抢走默认网络、且没有 DNS，导致「点了恢复联网，红果还是上不了网」。2.3.1 已删除该行为。
  - 因此**不要再开启系统 VPN 里的「始终开启 VPN」和「屏蔽无 VPN 的连接」**：它们会和开关互相打架，系统会强行把 VPN 拉起来，App 又停掉它。
  - 界面与通知栏显示的状态，均以「拦截隧道是否真的建起来」为准；若显示「断网没生效」，点按钮会直接重试，而不是把开关误关掉。

## 4. 构建

```bash
cd /www/wwwroot/hongguo-netlock
export ANDROID_HOME=/opt/android-sdk ANDROID_SDK_ROOT=/opt/android-sdk
./gradlew :netlock:assembleRelease --no-daemon --offline

# 产物
netlock/build/outputs/apk/release/netlock-release.apk
```

- 签名：`apk/jingxuan.keystore`，别名 `jingxuan`；密码不写进仓库，改为本机根目录 `local.properties` 里的 `RELEASE_STORE_PASSWORD` / `RELEASE_KEY_PASSWORD`（该文件已被 `.gitignore` 忽略）
- 包名：`com.jingxuan.netlock`
- minSdk 26 / targetSdk 34 / compileSdk 34

## 7. 手机上必须做的设置

### 通用
1. 首次使用 → 允许「VPN 连接请求」；
2. Android 13+ 会弹通知权限，必须允许——否则常驻通知和开关在通知栏看不到。
3. 状态页点「悬浮球」→ 允许「显示在其他应用上层」，屏幕上会出现半透明小球（2.7.0 起的主要保活方式）；
4. 打开 App 后按返回键，卡片会留在最近任务里。

### 备选：完全不用常驻（2.4.0 新增）
如果只想要「一次设置、以后都不用管」，可以完全不用本 App 的 VPN 通道：
1. 状态页底部点「系统联网控制」（通知栏第三个按钮也可），进入系统流量/联网管理页；
2. 找到「红果短剧」，把「移动数据」和「WLAN」都关掉（部分 ColorOS 版本路径：设置 → 移动网络 → 流量管理 → 应用联网权限）；
3. 回到本 App 点「退出常驻」，之后再被系统杀掉也不影响断网；
4. 要看剧时去系统里把开关打开即可。

> 系统不把这个开关开放给第三方 App，所以只能跳转，不能替你点。这条路的好处是**零后台进程**；代价是每次手动两下。

### OPPO ColorOS 17
1. 设置 → 应用 → 应用管理 → 红果断网 → **耗电管理 → 允许完全后台行为**
2. 设置 → 应用 → **应用自启动** → 红果断网 → 允许
3. 应用管理 → 红果断网 → **关联启动** → 允许
4. 设置 → 电池 → 更多设置 → **睡眠待机优化 → 关闭**
5. 最近任务里把红果断网**下拉锁定**
6. **系统 VPN 设置里不要开启「始终开启 VPN」和「屏蔽无 VPN 的连接」**
   - 这两项会让系统强行保持 VPN 连接，与 App 的「联网/断网」开关打架：表现为点了恢复联网，红果仍然上不了网。2.3.1 已不再保留空隧道，请把这两项关掉。
7. 系统 VPN 设置在「设置 → 连接与共享 → VPN」；2.6.0 起状态页不再放这个链接。

## 8. 已知问题

- 2.7.0 起主要靠悬浮球保活，清理最近任务不会带走它；但「强制停止」或 ColorOS 深度清理仍会杀进程，之后靠开机/锁屏/网络广播和 90 秒看门狗自愈，最长约 1 分钟内会重新出现，期间红果会短暂恢复联网。Android 上不存在真正「杀不死」的合规方案，要绝对可靠就配合第 7 节「系统按应用断网」；
- 断网期间状态栏会有 VPN 钥匙图标（正常）；联网后钥匙应消失，若一直存在说明系统 VPN 设置里还开着「始终开启 VPN」，请关掉；
- 断网只拦**新的网络请求**：如果广告素材在断网前已经被红果缓存到本地，可能还会播一次；先断网、再打开红果最稳；
- 本方案是「整断网络」，不是「只拦广告域名」。红果的广告请求大量走自建 HTTPDNS / 直连 IP，按域名拦截既拦不准也容易误伤正常播放；
- 重启手机后会由开机广播自动拉起常驻服务和断网状态；
- 部分定制系统仍可能杀掉服务。2.4.0 已加自愈（60 秒心跳 / 90 秒看门狗 / 亮屏与网络切换自检 / 划掉卡片 3 秒后复活），被杀后一般能在 1~2 分钟内恢复；要彻底不依赖进程请用第 7 节的「备选：完全不用常驻」；
- 「退出常驻」会停止服务并移除通知，但**再次打开 App 会自动恢复常驻**；
- 2.6.0 起状态页只剩背景图和一行状态：联网 = `on` 图，已断网 = `off` 图，点一下切换；底部两个小入口是「系统联网控制」「退出常驻」；
- 只针对包名 `com.phoenix.read`，红果若更换包名需同步修改 `BlockService` 与 `<queries>`。
